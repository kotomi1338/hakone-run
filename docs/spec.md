# 箱根駅伝 連打ランゲーム 仕様まとめ

Nov 7, 2026 · @Kotomi Mukohira

## 概要

箱根駅伝の10区間をスペースキーの連打で走り抜け、獲得ポイントでランキングを競うWebブラウザ向けのPCゲーム。

- **プラットフォーム**：Webブラウザ（PC）
- **プレイ人数**：1人（CPUランナーは登場しない）
- **ステージ構成**：2ステージ・全10区間

| ステージ | 区間 | ルート | 特徴 |
| --- | --- | --- | --- |
| 第1ステージ（往路） | 1〜5区 | 大手町 → 芦ノ湖 | 平坦から始まり、5区の山登りがクライマックス |
| 第2ステージ（復路） | 6〜10区 | 芦ノ湖 → 大手町 | 6区の山下りから始まり、10区のゴールへ |

## 操作

操作はスペースキーとエンターキーの2つだけ。

| キー | 役割 |
| --- | --- |
| スペースキー（メイン） | 連打して走る。連打の速さが走る速さになるが、連打しすぎると転ぶので遅くなる。 |
| エンターキー（サブ） | タイミングよく押して、給水・応援を受け取る／黒たまごを拾う／襷を渡す |

## レースのルール

各中継所に制限時間があり、間に合えば襷をつなげる。間に合わなければ繰り上げスタートになる。

1. 1区から順に走り、中継所で襷を渡して次の区間へ進む
2. 中継所に制限時間内に着けないと、繰り上げスタート（襷が途切れる）になる。レースは続くが、全区間ボーナスはもらえない
3. 第1ステージ（往路）は5区の芦ノ湖ゴールで終了し、第2ステージ（復路）は6区の芦ノ湖スタートから始まる
4. 10区で大手町にゴールしたら、ポイントを集計してランキングに登録する

## ポイントの仕組み

最終スコアはタイムポイントと各種ボーナスの合計で、6区以降に獲得したポイントは1.2倍になる。

| ポイント | 対象区間 | もらえる条件 | 操作 |
| --- | --- | --- | --- |
| タイムポイント | 全区間 | 区間タイムが速いほど多い | スペース連打 |
| リズムボーナス | 全区間 | 一定のテンポで連打し続けるとコンボがつながり、倍率が上がる | スペース連打 |
| 坂ボーナス | 5区・6区 | 5区：上り坂の約1kmの区切りごとに勢いを保てると加算、最高地点に着いたとき上り全体で勢いを保てていれば大きめのボーナス。6区：下りで転ばずに目安の勢いをキープした距離だけ加算（時間だと縮尺で変わるため距離にした） | スペース連打 |
| 給水・応援 | 全区間 | マークが出たところでタイミングよく押すと受け取れる。早すぎ・遅すぎは取り損ね | エンター |
| 黒たまご | 5区・6区中心 | コース上に出たところでタイミングよく押すと拾える。大きめのポイント | エンター |
| 襷リレー | 各中継所 | ゲージに合わせて押す。ぴったりでPERFECT、少しずれてGOOD、大きくずれると減速。速く飛び込むほどゲージが速い | エンター |
| 全区間ボーナス | ゴール時 | 10区間すべて制限時間内に中継所へ着き、襷をつないだら自動で加算 | なし |
| 7区・日差し給水 | 7区 | 日差しが強い場所で給水を受け取るとポイント2倍 | エンター |
| 10区・ラストスパート | 10区 | 日本橋を越えた後のラスト約3kmの連打の速さで大きなボーナス。この区間は押しすぎで転ばず、最高速度を超えてダッシュできる | スペース連打でダッシュ可能。 |

6区以降の1.2倍と、7区・10区の専用ボーナスは、山の区間でついた差を後半で挽回できるようにするための仕組み。

## 区間ごとの特徴

実際の箱根駅伝の地形をもとに、坂の重さと区間専用のボーナスを割り当てる。

| 区間 | ルート | 距離（km） | 地形 | ゲーム上の要素 |
| --- | --- | --- | --- | --- |
| 1区 | 大手町 → 鶴見 | 21.3 | ほぼ平坦。終盤に六郷橋の小さな上り下り | チュートリアル的な区間 |
| 2区 | 鶴見 → 戸塚 | 23.1 | 15km過ぎに権太坂、ラスト3kmに「戸塚の壁」 | 小さな坂が2回 |
| 3区 | 戸塚 → 平塚 | 21.4 | 序盤は遊行寺坂の下り、後半は海沿いの平坦路 | スピードが出やすい |
| 4区 | 平塚 → 小田原 | 20.9 | 小さな起伏と終盤のゆるい上り | 5区への助走 |
| 5区 | 小田原 → 芦ノ湖 | 20.8 | 標高874mの国道1号最高地点まで上り、最後は下る | 坂ボーナス、黒たまご。第1ステージのクライマックス |
| 6区 | 芦ノ湖 → 小田原 | 20.8 | 最初の約4kmを上ったあと、一気に下る | 坂ボーナス（連打しすぎると転ぶ）、黒たまご。ここからポイント1.2倍 |
| 7区 | 小田原 → 平塚 | 21.3 | 気温の変化がいちばん大きい | 日差しが強い場所の給水でポイント2倍 |
| 8区 | 平塚 → 戸塚 | 21.4 | 湘南新道から約9kmの上り坂 | 特別なボーナスなし |
| 9区 | 戸塚 → 鶴見 | 23.1 | 2区の逆向き。権太坂を下る | 特別なボーナスなし |
| 10区 | 鶴見 → 大手町 | 23.0 | ほぼ平坦。日本橋を抜けてゴールへ | ラストスパートボーナス |

区間の距離と地形：[箱根駅伝2027特集](https://eleschool-compass.com/school-matching/shinbun/topics/hakone-ekiden-2027.php)、[箱根駅伝 区間ごとの見どころ（All About）](https://news.allabout.co.jp/articles/o/26877/)、[地図研究家と見る往路ルート（Number Web）](https://number.bunshun.jp/articles/-/846498)

## ランキングと公平性の方針

ポイントは自分の走りだけで決まり、遊ぶ順番や他のプレイヤーの記録に左右されないようにする。

- 区間新記録など、他のプレイヤーの記録と比べるボーナスは入れない（後から遊ぶ人が不利になるため）
- CPUランナーは登場しない。ごぼう抜きや区間賞のような、相手が必要なボーナスも入れない
- 給水・応援・黒たまごの位置は全員同じ（固定配置）。運の要素を入れない
- ランキングは最終スコアで並べる

## デバッグ用の管理画面

ゲームの数値をプレイしながら調整するために、開発用の管理画面を用意する。

| 機能 | 内容 |
| --- | --- |
| コースの縮尺 | 区間の距離は実際の箱根駅伝に準拠し、縮尺（最高速で1kmを走る秒数）だけを全区間共通で変えられる |
| 連打のジャストタイミング | リズムボーナスの基準になる、スペースキーを押す間隔（ミリ秒）を調整できる |
| ポイント計算の見える化 | 最終ポイントがどう計算されたかを、項目ごと・区間ごとにわかりやすく表示する |

### あると便利な機能（候補）

- [ ] ジャストタイミングの許容幅（何ミリ秒ずれてもコンボが続くか）の調整
- [ ] 各ボーナスのポイント数、6区以降の倍率、中継所の制限時間の調整
- [ ] 好きな区間からすぐに遊べる区間ジャンプ
- [ ] プレイ中の連打間隔・コンボ数・速度をリアルタイム表示
- [ ] 調整した設定の保存と書き出し（JSONなど）
- [ ] 公開版では管理画面を無効にする（ランキングの不正防止）

## 実装メモと、作ってから調整する項目

数値の配分は、動くものを作って遊んでから決める。

### 実装メモ

- スペースキーの押しっぱなし対策：`keydown` で `e.repeat` が true のものは無視する
- ページのスクロール防止：スペースキーとエンターキーで `preventDefault()` を呼ぶ
- 自動連打ツール対策：1秒あたりの連打回数に上限を設ける

### 調整する項目

- [ ] タイムポイントと各ボーナスの配分
- [ ] 6区以降の倍率（今は1.2倍）
- [ ] 各中継所の制限時間
- [ ] 連打回数の上限値
- [ ] 給水・応援・黒たまごの数と配置
- [ ] 給水や襷の場面以外でエンターキーを押したときの扱い（何も起きないか、少しペナルティか）
- [ ] ランキングにポイントの内訳を表示するか

## 技術スタック

Void（Viteベース）で作り、Cloudflareにデプロイする。ゲーム本体は2DゲームエンジンのPhaserを使う。

| 役割 | 技術 | 選ぶ理由 |
| --- | --- | --- |
| 土台・デプロイ | Void ＋ TypeScript | ゲーム画面、API、DBを1つのプロジェクトにまとめ、`void deploy` でCloudflareに公開できる |
| ゲーム本体 | Phaser | スプライトアニメ、トゥイーン、カメラ、キー入力、シーン切り替えがそろっている |
| 演出アニメーション | Phaserのトゥイーン ＋ スプライトシート | 走るモーション、襷を渡す動き、黒たまごを拾うポップ、PERFECT表示など。連打の速さに合わせて走るアニメの再生速度を変える |
| 背景 | 多重スクロール（パララックス） | 遠景・中景・手前を違う速さで流して奥行きを出す。坂は地面の傾きとカメラで表現する |
| ランキング | VoidのAPIルート ＋ D1（SQLite） | スコアの保存と取得 |
| 管理画面 | lil-gui（またはTweakpane）をゲーム画面に重ねる | スライダーで値を変えると、プレイ中にその場で反映される |
| 設定の保存 | JSONの書き出し、またはKV | 調整した値を本番用の設定として読み込む |

- 管理画面は `import.meta.env.DEV` のときだけ読み込み、公開版に含めない
- スコアはサーバー側で、連打の上限から計算した最大スコアを超えていないかチェックする

[Void（GitHub）](https://github.com/voidzero-dev/void/wiki)

## 開発の進め方（VSCode ＋ Claude Code）

この仕様書をClaude Codeに読ませ、「連打で走る」だけの最小版から少しずつ機能を足していく。

### 準備

1. Voidのハンズオンと同じ手順で、新しいプロジェクトを作り、Gitを初期化する
2. この仕様書をMarkdownで書き出し、`docs/spec.md` としてプロジェクトに置く
3. `CLAUDE.md` を作り、「仕様は `docs/spec.md` を参照」「技術スタックはVoid・Phaser・TypeScript」「1機能ずつ実装して動作確認する」などのルールを書く
4. VSCodeでプロジェクトを開き、Claude Codeを起動する

### 作る順番

1. **連打で走る**：1区だけ。キャラは四角でよい。スペースキーの連打、押しっぱなし対策、スクロール防止まで
2. **管理画面**：lil-guiを入れ、区間の秒数とジャストタイミングを変えられるようにする。早めに作ると、以降の調整が楽になる
3. **レースの流れ**：10区間、2ステージ、中継所の襷リレー、制限時間と繰り上げスタート
4. **ポイント計算**：タイム・リズム・襷・全区間ボーナス、6区以降の倍率。管理画面に計算の内訳を表示する。計算の処理は画面から切り離して、テスト（Vitest）を書かせる
5. **坂とアイテム**：5区・6区の坂と坂ボーナス、給水・応援・黒たまごのタイミング押し、7区・10区のボーナス
6. **見た目と演出**：スプライトアニメ、多重スクロールの背景、PERFECT表示などの演出
7. **ランキング**：APIとD1でスコアを保存し、サーバー側で不正な値をチェックする
8. **公開**：管理画面を無効にした公開版を `void deploy` でデプロイする

### Claude Codeを使うときのコツ

- 1回の依頼は上の1ステップ分だけにする。「仕様書の‘操作’と‘レースのルール’を読んで、まず連打で走るところまで作って」のように、仕様書のどこを使うかも伝える
- 大きめの機能は、先にプランモードで実装の計画を出してもらい、確認してから作らせる
- 1ステップごとにブラウザで遊んで確認し、動いたらコミットする。壊れても戻せる
- 仕様を変えたら、この仕様書と `docs/spec.md` の両方を更新する
- 早いうちに一度デプロイして、Cloudflare上でも動くことを確かめておく
